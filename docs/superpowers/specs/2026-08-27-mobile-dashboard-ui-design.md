# 行動版飲水首頁 UI 設計規格

## 目標

將現有 React Dashboard 改造成固定手機寬度的高擬真飲水 App 首頁。畫面在桌面瀏覽器中置中顯示手機版，不另外延伸桌面資訊架構。核心任務是讓使用者在數秒內掌握今日飲水進度、智慧水杯連線狀態，並能一鍵記錄飲水量。

## 已確認範圍

- 本輪只重做首頁 `DashboardView`。
- 保留現有 React、TypeScript、Context 與 API 資料流。
- 桌面環境固定顯示置中的手機版內容。
- 不新增成就功能；底部導覽以「首頁、統計、中央新增、裝置、我的」呈現。
- BLE 狀態整合進主要飲水進度卡，不保留獨立大型 BLE 卡。
- 正式 UI 使用 Lucide 圖示與自訂 SVG/CSS 插畫，不直接使用 AI 提案圖作為產品切圖。

## 視覺方向

- 類型：健康／生活風格，安靜、清爽、可信任。
- 背景：暖白色；卡片為白色，搭配非常柔和的藍灰陰影。
- 強調色：明亮鈷藍與天空藍，只用於進度、選中狀態與主要操作。
- 文字：深藍黑主文字、藍灰次要文字；大數字優先於標籤。
- 元件：24px 左右圓角、8pt 間距系統、至少 44px 點擊區。
- 避免：玻璃擬態、強烈漸層、厚重陰影、照片背景、裝飾性雜訊。

## 畫面結構

### 1. 頂部問候

- 顯示依時段切換的問候語與使用者名稱。
- 次行顯示簡短的補水提醒。
- 右側保留通知圖示與未讀紅點，現階段為視覺入口，不新增通知後端功能。

### 2. 今日飲水主卡

- 左側為環形進度與核心數字：今日累積水量、每日目標與達成率。
- 右側為自訂 SVG 玻璃杯插畫；水位依達成率變化，上限為 100%。
- 卡片下方為智慧水杯狀態列：
  - 已連線：藍色狀態點、`智慧水杯已連線`、目前重量與前往 BLE 頁面的箭頭。
  - 未連線：灰色狀態點、`智慧水杯未連線`、`前往連線`。
  - 連線中：顯示輕量動畫與 `連線中`。
- 點擊狀態列後切換到既有 BLE 頁面。

### 3. 快速喝水

- 提供 150、250、350、500 ml 四個大尺寸按鈕。
- 點擊後沿用 `logWaterRecord`，事件類型為 `drink`。
- 成功後更新進度、紀錄並顯示成功 Toast。
- 重複點擊期間暫時鎖定該按鈕，避免重複送出。

### 4. 今日紀錄

- 顯示最近三筆飲水紀錄，內容只保留杯子圖示、水量與時間。
- `查看全部` 導向既有歷程頁面。
- 無資料時顯示友善空狀態與第一次記錄的提示。
- 補水事件以不同的小圖示或次要標記區分，但不增加表格欄位。

### 5. 小提醒

- 顯示一條低視覺權重的補水提示。
- 文案為本地靜態內容，不新增提醒排程或通知功能。

### 6. 底部導覽

- 固定在手機畫面底部，項目為首頁、統計、中央新增、裝置、我的。
- 中央新增按鈕開啟現有手動記錄能力的輕量輸入區；本輪可先使用內嵌面板，不新增複雜 Modal 系統。
- 導覽映射：首頁 → `dashboard`、統計 → `stats`、裝置 → `devices`、我的 → `settings`。
- 既有 BLE 與歷程頁面仍可由首頁卡片與紀錄卡進入。

## 元件邊界

- `DashboardView`：組合資料與首頁區塊，保留記錄飲水及導頁行為。
- `HydrationHero`：負責進度、玻璃杯插畫及 BLE 摘要。
- `WaterGlassIllustration`：純視覺 SVG，輸入標準化進度值。
- `QuickDrinkGrid`：顯示快速水量選項與送出狀態。
- `TodayRecordsCard`：顯示最近三筆紀錄與空狀態。
- `HydrationReminder`：靜態提醒橫幅。
- `Navbar`：改為固定手機底部導覽並維持既有 `ActiveTab` 切換介面。

這些元件只透過 props 接收所需資料，避免在純顯示元件內直接讀取 Context。

## 資料映射

- `dailyStats.totalMl` → 今日飲水量。
- `dailyStats.goalMl` 或 `user.dailyGoalMl` → 每日目標。
- `totalMl / goalMl` → 達成率；目標為 0 或缺值時回退為 0%。
- `bleStatus` 與 `bleSummary.currentWeight` → 智慧水杯狀態與重量。
- `records` → 依時間取最近三筆顯示。
- 快速喝水 → `logWaterRecord({ eventType: 'drink', amountMl, occurredAt })`。

## 狀態與錯誤處理

- 初始載入：保留畫面骨架，不以全卡 Spinner 取代內容。
- API 失敗：沿用離線佇列；Toast 告知已暫存並等待同步。
- 快速記錄送出：按鈕顯示處理中並防止同一選項連點。
- BLE 未連線或無摘要：不顯示假重量，改顯示連線入口。
- 水量超過目標：主進度環封頂 100%，文字可顯示真實百分比。
- 空紀錄：顯示引導文案，不渲染空白列表。

## 動效與回饋

- 進度環與玻璃杯水位在資料更新時以 300–500ms 平滑過渡。
- 快速記錄成功時，按鈕短暫顯示勾選狀態，並觸發既有成功 Toast。
- 達成 100% 時可顯示一次克制的高光或小型粒子效果；不新增持久動畫。
- 遵守 `prefers-reduced-motion`，使用者偏好減少動效時停用非必要動畫。

## 可用性與無障礙

- 所有圖示按鈕提供 `aria-label`。
- 不以顏色作為連線狀態的唯一資訊。
- 點擊區至少 44×44px。
- 主要與次要文字需符合 WCAG AA 對比。
- 鍵盤焦點樣式清楚可見。
- SVG 插畫為裝飾用途時設為 `aria-hidden`。

## 驗證方式

- TypeScript 與 Vite production build 通過。
- 現有 API、同步與 BLE 單元測試維持通過。
- 新增 Dashboard 元件測試，至少覆蓋：
  - 正確計算與封頂進度。
  - 快速水量按鈕送出正確 payload。
  - BLE 已連線、未連線與連線中狀態。
  - 今日紀錄有資料與空狀態。
- 以 390×844 作為主要視覺尺寸，並檢查 375px 寬度不產生水平捲動。
- 桌面瀏覽器確認手機容器置中、底部導覽不超出容器。

## 不在本輪範圍

- 其他頁面的完整視覺改版。
- 通知中心、提醒排程或推播後端。
- 成就、徽章或遊戲化系統。
- 新增 API、修改資料庫或韌體協議。
- 將網站打包為原生 iOS／Android App。
