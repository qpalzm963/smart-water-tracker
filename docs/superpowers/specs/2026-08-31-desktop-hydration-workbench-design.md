# 桌面飲水工作台設計規格

## 目標

將目前以行動版與高科技 HUD 為主的飲水首頁，改成一般桌面 Web 的「飲水工作台」。使用者開啟首頁後，先看到今日總量與完成率，接著能在同一個工作面快速記錄容量，再查看今日紀錄與本週摘要。

## 已確認範圍

- 本輪重構登入後的首頁 `DashboardView` 與其桌面導覽呈現。
- 以已核准的「01｜桌面工作台」示意為視覺基準。
- 不特別設計新的手機版；既有窄視窗排版保留為基本降級，桌面寬度是主要驗證目標。
- 保留既有 React、TypeScript、Context、API、離線佇列、BLE 與紀錄刪除流程。
- 不改後端、資料庫、韌體、登入流程或 API 契約。
- 移除首頁對 3D／科技 HUD 的視覺依賴；飲水數字與進度改由清楚的 DOM 內容呈現。

## 視覺方向

- 概念：像每天會打開的工作工具，而不是展示型儀表板。
- 背景：極淡灰綠 `#f7f9f6`，主內容維持白色表面。
- 文字：深墨綠 `#202b28`；輔助文字 `#75817b`。
- 強調色：酸橙綠 `#b7d568` 只用於進度、選中狀態與連線點；深綠 `#26372f` 作為主要操作按鈕。
- 表面：1px 細描邊、4–8px 小圓角、低幅度陰影；避免漸層、玻璃擬態、霓虹、裝飾性網格與重複膠囊。
- 字級：標題緊湊但不誇張；飲水量採 tabular figures，讓數字更新不造成跳動。
- 圖示：沿用 `lucide-react`，線寬 1.5–2；不使用 emoji 作為介面圖示。

## 首頁結構

### 1. 桌面頂部導覽

- 左側顯示 `WATER / TRACKER` 品牌文字。
- 中間依序提供「總覽、統計、裝置、我的」導覽，維持既有 `ActiveTab` 行為。
- 右側顯示 BLE 連線狀態、使用者縮寫與名稱。
- 快速新增仍由中央新增入口觸發既有 `#quick-drink` 捲動行為，但在桌面改為頂部「新增紀錄」文字按鈕，不做漂浮圓形按鈕。

### 2. 頁面工具列

- 顯示當日日期與「今天的飲水」標題。
- 右側提供「新增紀錄」與更多選項按鈕。
- 工具列只承擔頁面識別與入口，不重複顯示進度數字。

### 3. 工作區左欄：今日進度與紀錄

- 顯示今日總量、每日目標、完成率、進度條與剩餘容量。
- 顯示最近三筆飲水紀錄：時間、容量、來源；保留既有刪除操作與「查看全部」導覽。
- 空狀態仍顯示可理解的下一步提示。
- 不顯示水杯插畫、3D 場景、HUD 軸線或動畫裝飾。

### 4. 工作區右欄：快速記錄與提醒

- 保留 150、250、350、500 ml 四個快捷容量，沿用既有忙碌、成功、錯誤與離線同步狀態。
- 顯示目前時間與「輸入其他容量」入口；自訂容量仍可在後續流程擴充，不在本輪新增資料行為。
- 顯示下一次提醒、提醒容量、智慧水杯連線狀態與目前重量；沒有重量時不建立假資料。

### 5. 底部摘要

- 使用 `weeklyStats` 顯示週一至今日的完成量柱狀摘要。
- 顯示今日喝水次數與平均每次容量。
- 若週資料尚未載入，顯示穩定的空值狀態，不造成版面位移。

## 元件與資料邊界

- `DashboardView`：讀取 Context、組合桌面工作區、管理快速記錄與刪除狀態、傳入 `weeklyStats`。
- `TechDashboardHeader`：保留既有 props 與通知行為，改成一般桌面頁首語意；不再使用 HUD／科技標籤作為主要文案。
- `HydrationHero`：改為 DOM-only 的今日進度卡，移除 `HydrationScene`、環形場景與科技軸線 props。
- `QuickDrinkGrid`：保留既有水量與狀態邏輯，改成右欄操作卡的語意化標題。
- `TodayRecordsCard`：保留排序、查看全部與刪除行為，改為桌面表格式排列。
- `DashboardWeekSummary`：新元件，只負責將 `WeeklyStats` 轉成週摘要視覺與今日統計。
- `Navbar`：保留既有 `ActiveTab` 與 `onAdd` API；桌面外觀由 CSS 改為頂部導覽，避免改動其他頁面的導覽行為。

## 狀態與互動

- `busyAmount !== null` 時停用全部快捷容量，按鈕顯示「記錄中」並保留可見焦點。
- 成功記錄顯示既有勾選回饋與 Toast；離線佇列仍顯示「已暫存」訊息。
- API 失敗沿用既有錯誤 Toast；不更新進度或紀錄列表。
- BLE 狀態使用文字加圓點與 Lucide 圖示，不以顏色作為唯一資訊。
- 互動按鈕維持至少 44px 高度、可見 focus ring 與 hover 邊框變化。
- 不新增持續動畫；保留既有 `prefers-reduced-motion` 全域規則。

## 無障礙與響應式

- 桌面主要內容最大寬度 1,280px，左右留白隨視窗增加。
- 主要工作區在寬度 ≥ 900px 使用左 1.5fr／右 .88fr；小於 900px 依序堆疊，不產生水平捲動。
- 所有圖表柱狀只作為數據的輔助呈現，文字摘要仍提供完整數值。
- 進度百分比、總量、目標與提醒容量皆以 DOM 文字提供。
- 導覽按鈕使用 `aria-current`；圖示按鈕提供 `aria-label`。

## 驗證方式

- `npm run test --workspace app`：既有 view-model、API、同步與 BLE 測試保持通過。
- `npm run build --workspace app`：TypeScript strict build 與 Vite build 通過。
- 瀏覽器檢查 1440×900 與 1280×720：確認頂部導覽、兩欄工作區、紀錄列與週摘要不溢出。
- 操作檢查：切換導覽、點擊四個快速容量、確認成功／錯誤 Toast、開啟 BLE 頁面、查看全部與刪除紀錄。
- 窄視窗降級檢查：工作區改為單欄，按鈕與文字仍可讀且不水平溢出。

## 不在本輪範圍

- 其他頁面的資訊架構重做。
- 新增自訂容量輸入、提醒排程編輯或新的後端資料欄位。
- 新增 3D、動畫場景、遊戲化、成就或社交功能。
