# Three.js 高科技飲水首頁設計規格

## 目標

將既有 React 飲水首頁改造成「精密水科技」風格：以可互動的 3D 玻璃杯呈現今日飲水進度，搭配深海藍介面、能量青光、即時 HUD 與克制的科技動效。核心操作仍由清晰且可存取的 React DOM 元件承擔，避免為了視覺效果犧牲快速記錄、資訊辨識與手機效能。

## 已確認範圍

- 本輪只重構首頁 `DashboardView`，不改其他頁面的資訊架構。
- 使用 React Three Fiber 建立 Three.js 場景，Motion for React 負責 DOM 動效。
- 保留既有 React、TypeScript、Context、API、離線同步與 BLE 資料流。
- 不修改後端、資料庫、韌體或 BLE 協議。
- 不新增成就、遊戲化或通知後端功能。
- 所有介面圖示使用 Lucide 或自訂向量圖形，不使用 emoji。

## 視覺方向

- 概念：精密水科技、智慧硬體控制中心、深海光學。
- 背景：深海藍至近黑藍，搭配低對比網格與局部徑向光。
- 強調色：冰藍、科技藍與能量青；霓虹僅用於即時狀態、進度與互動回饋。
- 表面：深色半透明面板、細描邊、低亮度內高光，不使用大量玻璃擬態疊層。
- 文字：主要資訊保持繁體中文；短小的英文 HUD 標籤只作為視覺輔助，不取代核心中文資訊。
- 數字：飲水量、百分比、重量與時間採等寬數字呈現，避免更新時跳動。
- 動效：穩定、精密、有物理感；避免持續強烈閃爍、過量粒子與遊戲化特效。

## 首頁結構

### 1. 系統問候列

- 顯示時段問候、使用者名稱與簡短狀態摘要。
- 右側顯示連線／系統狀態入口，保留可理解的中文標籤。
- 首次進場以短距離位移與透明度漸入，不逐字播放。

### 2. 3D 飲水主卡

- 左側 DOM HUD 顯示今日飲水量、目標與實際達成率。
- 右側 `HydrationScene` 顯示 3D 玻璃杯；液面高度依封頂後的 `0..100` 進度映射。
- 場景包含冰藍玻璃材質、半透明水體、柔和環境光、環形空間標記與低亮度掃描線。
- 使用者可拖曳讓水杯小幅旋轉，放開後以彈簧動效回到展示角度。
- 不提供任意縮放、無限制旋轉或會妨礙頁面捲動的手勢。
- 飲水成功時只觸發一次水面波紋、光環擴散與數字遞增。

### 3. 智慧水杯狀態列

- 顯示 BLE 已連線、連線中或未連線的文字狀態。
- 已連線且有摘要時顯示目前重量；沒有重量時不建立假資料。
- 點擊後沿用既有 BLE 頁面導覽。
- 連線狀態只更新 HUD，不重建整個 Three.js 場景。

### 4. 快速記錄

- 保留 150、250、350、500 ml 四個選項。
- 點擊時使用 Motion 提供按壓回饋，請求期間停用所有水量按鈕。
- 成功後選中按鈕顯示 Lucide 勾選圖示，並通知 3D 場景觸發一次波紋。
- 失敗時顯示既有錯誤 Toast，不更新液面或播放成功動畫。
- 離線佇列成功接收時沿用現有提示，並視為本機記錄成功。

### 5. 今日紀錄與底部導覽

- 今日紀錄改為深色資料面板，維持最新三筆與「查看全部」入口。
- 底部導覽沿用首頁、統計、中央新增、裝置、我的映射。
- 選中狀態使用能量青文字與細光線，不以光暈作為唯一辨識方式。

## 元件架構

- `DashboardView`：讀取 Context、組合頁面、執行快速記錄並管理一次性成功事件。
- `TechDashboardHeader`：問候與系統摘要。
- `TechHydrationHero`：組合 HUD、3D 場景與 BLE 狀態列。
- `HydrationScene`：建立 React Three Fiber `Canvas`，管理相機、燈光、畫質、可見性與錯誤邊界。
- `TechWaterGlass`：玻璃杯幾何、材質、旋轉限制與回正互動。
- `AnimatedWater`：液面高度、輕量晃動與一次性波紋。
- `TechHud`：使用 DOM 顯示飲水量、百分比與目標。
- `TechQuickDrinkGrid`：快速水量控制、送出與成功狀態。
- `StaticWaterGlass`：WebGL 不支援或降級時使用的靜態 SVG。

Three.js 元件只接收標準化的進度、成功事件序號、是否允許動效等 props，不直接讀取 Context。這可避免資料請求造成場景重建，也讓 3D 與業務邏輯能分開測試。

## 技術選擇

- `three`：3D 場景與材質基礎。
- `@react-three/fiber@8`：React 18 對應的 Three.js renderer。
- 場景 helper：以本地 `useFrame` 實作固定成本的漂浮效果，避免為單一 helper 引入額外套件。
- `motion`：DOM 進場、按壓、成功回饋與減少動態偵測。
- CSS：靜態顏色、表面、描邊、Focus 與簡單 Hover 狀態。

不加入 GSAP、物理引擎、影片素材或外部 3D 模型。玻璃杯與水體使用程式化幾何建立，減少資產載入與授權成本。

## 資料與動畫狀態

- `dailyStats.totalMl` → HUD 今日飲水量。
- `dailyStats.goalMl` 或 `user.dailyGoalMl` → 每日目標。
- `totalMl / goalMl` → 真實百分比；液面顯示值封頂為 100%。
- `bleStatus` 與 `bleSummary.currentWeight` → 智慧水杯狀態列。
- `records` → 今日最近三筆紀錄。
- 快速記錄 → 既有 `logWaterRecord` 與離線同步流程。
- `successPulseId` → 每次成功遞增的數字，用來觸發一次性 3D 水波；不使用持續布林值避免漏播。

液面更新使用插值接近新高度，不直接跳值。HUD 數字與液面共享相同來源，但各自控制動畫，任何動畫中斷都不得影響實際資料。

## 效能與降級

- Canvas 只占主卡視覺區，不建立全頁 WebGL 背景。
- 裝置像素比例限制在 `1..1.5`，不啟用即時陰影、景深、Bloom 或全螢幕後製。
- 使用少量幾何、共用材質與固定燈光，避免每幀建立物件。
- 頁面不可見或首頁卸載時停止渲染與事件監聽。
- WebGL 初始化或場景渲染失敗時，由錯誤邊界顯示 `StaticWaterGlass`。
- `prefers-reduced-motion: reduce` 時停用漂浮、掃描、持續液面波動與數字滾動；保留即時數值與必要狀態變更。
- 降級只改變視覺呈現，不停用快速記錄、BLE 導覽或今日紀錄。

## 載入與錯誤處理

- 首頁資料載入時顯示穩定骨架，Canvas 使用固定高度避免版面位移。
- Three.js 模組載入期間顯示與場景尺寸相同的靜態水杯。
- WebGL 錯誤不使用全頁錯誤畫面，也不阻擋其他首頁操作。
- API 失敗沿用現有 Toast 與離線佇列，不由 3D 元件顯示業務錯誤。
- BLE 未連線時顯示清楚的「前往連線」入口，不播放模擬連線動畫。

## 無障礙與操作規則

- Canvas 標記為裝飾性視覺；飲水量、目標與狀態在 DOM 中完整提供。
- 拖曳水杯不是完成任務的必要操作，不影響鍵盤或觸控使用者取得資訊。
- 所有按鈕至少 44×44px，提供可見 Focus、Pressed、Disabled 與 Selected 狀態。
- 不以顏色、光暈或動畫作為狀態的唯一訊號。
- 文字與互動元件需符合 WCAG AA 對比；裝飾性低對比線條不承載資訊。

## 驗證方式

- 單元測試：進度與液面映射、目標為零、超過目標、一次性成功事件。
- 元件測試：快速記錄成功／失敗、BLE 三種狀態、WebGL 靜態降級。
- 回歸測試：既有 API、離線同步、BLE 協議與 Dashboard view-model 測試保持通過。
- Production build：TypeScript 與 Vite build 通過。
- 視覺檢查：390×844、375×812 與桌面置中手機容器。
- 實機檢查：Chrome 桌面與 Android Chrome；確認拖曳不搶走頁面垂直捲動。
- 效能檢查：一般手機目標 55–60 FPS，降低動態模式無持續動畫，場景卸載後無殘留 render loop。

## 不在本輪範圍

- 全 App 深色主題與其他頁面的 Three.js 改版。
- 自訂 GLSL 折射 Shader、粒子系統、音效或震動回饋。
- 雲端 3D 模型、外部貼圖或影片背景。
- 通知中心、成就系統、後端與韌體功能變更。
